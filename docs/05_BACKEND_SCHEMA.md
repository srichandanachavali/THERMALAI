# Backend Schema — Data Model & Auth Architecture

## Database Tables (MongoDB Collections)

### Reactor
| Field | Type | Description |
|-------|------|-------------|
| reactor_id | String | Unique reactor identifier |
| temperature | Number | Sensor reading in °C |
| pressure | Number | Sensor reading in bar |
| reaction_rate | Number | Normalized 0–1 |
| cooling_efficiency | Number | Normalized 0–1 |
| temp_rate_of_change | Number | °C/min delta |
| risk_score | Number | Ensemble ML score 0–100 |
| status | String | SAFE / WARNING / CRITICAL |
| label | String | Ground truth label (for training) |
| timestamp | Date | Reading timestamp (TTL indexed — expires after 7 days) |

### Alert
| Field | Type | Description |
|-------|------|-------------|
| reactor_id | String | Which reactor triggered the alert |
| alert_type | String | CRITICAL / WARNING / INFO |
| risk_score | Number | Score at time of alert |
| temperature | Number | Temperature at time of alert |
| pressure | Number | Pressure at time of alert |
| message | String | Human-readable alert description |
| resolved | Boolean | Default false; set via PUT /api/alerts/:id/resolve |
| createdAt | Date | Auto-generated by Mongoose |

### User
| Field | Type | Description |
|-------|------|-------------|
| username | String | Unique login name |
| password | String | bcrypt hash (never stored plain) |
| role | String | admin or operator |
| createdAt | Date | Auto-generated |

### Plant
| Field | Type | Description |
|-------|------|-------------|
| name | String | Plant name |
| location | String | Physical location |
| reactors | Array | List of reactor IDs belonging to this plant |
| createdAt | Date | Auto-generated |

## Relationships
- Alert references Reactor via `reactor_id` (string foreign key — not ObjectId)
- Plant contains array of reactor IDs
- No joins — MongoDB document model; reactors embedded/referenced by ID strings

## Auth Provider
Custom JWT-based authentication. No third-party auth provider.
- Login: POST `/api/auth/login` → bcrypt.compare → sign JWT with `JWT_SECRET`
- Token stored in localStorage (frontend)
- Middleware verifies JWT on all protected routes

## Row Level Security
Not applicable (MongoDB, not SQL). Access control enforced at the API route level via JWT middleware. Admin-only routes (simulate, register new user) check `req.user.role === 'admin'`.

## User Roles
- **admin** — full access: simulate runaway, view all dashboards, manage alerts, register new users
- **operator** — read access to dashboards and alerts, can resolve alerts, cannot simulate or register users

## Sensitive Fields
- `User.password` — stored as bcrypt hash with salt rounds; never returned in API responses
- `JWT_SECRET` — environment variable only; never committed to repo
- `EMAIL_PASS` — Gmail app password stored in environment variable
- `TWILIO_AUTH_TOKEN` — stored in environment variable

## File Storage
No file/blob storage in this application. All data is sensor readings and alerts stored in MongoDB.

## API Endpoints
### Auth
- `POST /api/auth/login` — authenticate user, return JWT
- `POST /api/auth/register` — admin-only, create new user

### Reactors
- `GET /api/reactors` — get all reactor readings (latest)
- `GET /api/reactors/:id` — get readings for specific reactor
- `POST /api/reactors/stream` — receive new sensor reading, call ML, broadcast via Socket.io
- `GET /api/reactors/:id/history` — historical readings for a reactor

### Alerts
- `GET /api/alerts` — get all alerts (newest first)
- `POST /api/alerts` — create new alert (used internally)
- `PUT /api/alerts/:id/resolve` — mark alert as resolved

### Plants
- `GET /api/plants` — get all plants with their reactor lists
- `GET /api/plants/:id` — get specific plant

### Simulation
- `POST /api/simulate/:id` — admin-only: trigger synthetic critical reading for reactor

### Health
- `GET /health` — service health check including ML API status
