## 1. What This System Does

ThermalAI predicts thermal runaway in chemical/pharmaceutical reactors **10–20 minutes before it occurs** using a dual ML ensemble. It provides real-time dashboards, AI explainability, predictive maintenance forecasts, and automatic SMS/email alerting.

**Version:** 1.0.0 (`backend/package.json:3`)  
**Deployed at:** https://thermalai-1.onrender.com (frontend), Render.com (all 3 services)

---

## 2. Architecture

```
React 19 (port 3000)
  └─ axios HTTP → Node/Express 5 (port 5000)
  └─ Socket.io WebSocket ←→ Node/Express 5 (port 5000)
                                └─ axios HTTP → Flask ML API (port 5001)
                                └─ mongoose → MongoDB Atlas
```

**Data flow per sensor reading:**
1. `stream_data.py` (or hardware) POSTs to `POST /api/reactors/stream`
2. `reactorController.js:48` calls `ML_URL/predict` → RF risk score
3. `reactorController.js:57` calls `ML_URL/predict-lstm` → LSTM risk score (backed by RF fallback; TF removed)
4. `reactorController.js:64-65` computes ensemble: `RF×0.40 + LSTM×0.60`
5. If WARNING/CRITICAL: saves Alert to MongoDB, emits `new_alert` via Socket.io
6. Emits `reactor_update` to all connected dashboards
7. On CRITICAL + cooldown cleared: calls `sendSMSAlert` + `sendEmailAlert`

**Ensemble thresholds** (`reactorController.js:67-69`): SAFE < 30, WARNING 30–69, CRITICAL ≥ 70

## 8. Authentication & Authorization

- JWT signed with `JWT_SECRET`, expires `24h` (`authController.js:50-54`)
- Token stored in `localStorage` key `thermalai_token` (`Login.js`, `App.js:19`)
- `ProtectedRoute` in `App.js:18-21` redirects unauthenticated users to `/select-plant`
- Token payload: `{ username, role, name }`
- Roles: `admin` (all routes + simulate), `operator` (monitor + resolve alerts)
- Admin check on `/api/simulate/:id` is **frontend-only** — no server-side guard (`server.js:33`)

## 14. Known Issues

### KI-1 — PLANT_CONTACTS map never matches (broken feature)
**File:** `alertController.js:22-24`  
**Problem:** Keys are `'plant-1'`, `'plant-2'`, `'plant-3'` but actual plant IDs are `PLANT_ALPHA`, `PLANT_BETA`, `PLANT_GAMMA` (`plantRoutes.js:7,17,27`). Additionally, `Alert` schema has no `plant_id` field — alerts are created with `reactor_id` ('A'–'E'). Per-plant contacts always fall back to `ALERT_PHONE`/`EMAIL_USER`.  
**Fix:** Either add `plant_id` to Alert schema and populate it during alert creation, or change PLANT_CONTACTS keys to `PLANT_ALPHA`/`PLANT_BETA`/`PLANT_GAMMA` and look up by reactor→plant mapping.

### KI-2 — 11 console.log calls remain in backend controllers
**Files:** `alertController.js:36,38,87,89` · `authController.js:15,24,28,56,85` · `reactorController.js:51,60,81`  
**Problem:** Bypasses Winston logging; logs don't go to `backend/logs/` in production.  
**Fix:** Replace with `logger.info()`/`logger.error()`/`logger.warn()`.

### KI-3 — App.test.js is default CRA placeholder
**File:** `frontend/src/App.test.js`  
**Problem:** Tests for `"learn react"` text that doesn't exist. Fails CI on every non-main push.  
**Fix:** Delete or replace with a real smoke test.

### KI-4 — No LICENSE file
**Problem:** README.md and badges declare MIT license but no `LICENSE` file exists in repo root.  
**Fix:** Create `LICENSE` file with MIT text.

### KI-5 — .vscode/settings.json committed
**File:** `.vscode/settings.json`  
**Problem:** Contains `"claudeCodeChat.permissions.yoloMode": true`. IDE config should not be version-controlled.  
**Fix:** Add `/.vscode/` to `.gitignore`, remove from tracking.

### KI-6 — backend/Plant.js is dead code
**File:** `backend/Plant.js`  
**Problem:** Full Mongoose schema that is never imported or used. Plant data is hardcoded in `plantRoutes.js`. The schema conflicts with CLAUDE.md which says models live in `backend/models/`.  
**Fix:** Delete the file.

### KI-7 — ML_URL duplicated constant
**Files:** `server.js:12`, `reactorController.js:6`  
**Problem:** Both read `process.env.ML_URL || 'http://localhost:5001'` independently. A future rename risks inconsistency.

### KI-8 — stream_data.py has uncommitted changes
**File:** `ml-model/stream_data.py`  
**Problem:** Working-tree modifies reactors B, C, E initial states from SAFE to WARNING/CRITICAL. Not committed.  
**Fix:** Commit or revert: `git checkout ml-model/stream_data.py`

### KI-9 — Render free tier spin-down
Services sleep after 15 min idle; cold start takes 30–60 s. ML service (`tensorflow-cpu` removed) now builds in ~45 s.

### KI-10 — /api/simulate/:id has no server-side auth guard
**File:** `server.js:33`  
**Problem:** Admin check is frontend-only. Any authenticated user (or unauthenticated caller with curl) can trigger simulate.

## 16. Critical Development Rules

1. **Backend: CommonJS only** — `require`/`module.exports` (`server.js`, all controllers, models, routes)
2. **Frontend: ES modules only** — `import`/`export` (all `.js` files under `frontend/src/`)
3. **Ports are fixed** — ML=5001, Backend=5000, Frontend=3000. Never mix in URLs.
4. **JWT_SECRET** — only in `backend/.env`. Never hardcode.
5. **Logging** — use `logger.info/warn/error` (from `backend/logger.js`). No `console.*` in backend.
6. **Develop on `develop`** — never commit feature work directly to `main`.
7. **Tests must pass** before merging — CI blocks the Render deploy hook on failure.
8. **`backend/.env` is gitignored** — never commit real secrets.
